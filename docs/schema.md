# Data Schema

No database. Data lives in Parquet files (plus one JSON) generated by `scripts/ingest.py` and loaded into pandas DataFrames at backend startup. All timestamps are UTC, timezone-aware (`datetime64[ns, UTC]`).

## 1. `backend/data/actuals.parquet`
Source: Elexon FUELHH, filtered to fuelType = WIND.
| Column | Type | Notes |
|---|---|---|
| start_time | datetime (UTC) | Settlement-period start, 30-min resolution. Primary key. |
| generation_mw | float64 | Actual wind generation in MW. |

Constraints: unique start_time, sorted ascending, generation_mw >= 0.

## 2. `backend/data/forecasts.parquet`
Source: Elexon WINDFOR.
| Column | Type | Notes |
|---|---|---|
| start_time | datetime (UTC) | Target time the forecast is for. |
| publish_time | datetime (UTC) | When the forecast was created. |
| generation_mw | float64 | Forecast wind generation in MW. |
| horizon_hours | float32 | (start_time - publish_time) in hours. Derived at ingest. |

Constraints: unique (start_time, publish_time), sorted by (start_time, publish_time), horizon_hours between 0 and 48 after filtering (negative horizons dropped).

## 3. `backend/data/meta.json`
```
{
  "data_start": "2026-01-01",
  "data_end": "2026-01-31",
  "default_cutoff_rule": "D-1 09:00 Europe/London",
  "horizons": [4, 12, 24, 36, 48],
  "ingested_at": "ISO8601",
  "row_counts": {"actuals": 0, "forecasts": 0}
}
```

## 4. Raw-to-clean field mapping
| Elexon field | Clean column |
|---|---|
| startTime | start_time |
| publishTime | publish_time |
| generation | generation_mw |
| fuelType | filter only (WIND), not stored |

## 5. Derived (in memory, not stored)
- `decision_forecast`: one row per start_time in the delivery day: start_time, publish_time, generation_mw.
- `aligned`: forecast joined to actual on start_time: start_time, forecast_mw, actual_mw, error_mw (= forecast - actual), abs_error_mw, horizon_hours, publish_time.

## 6. API response models (Pydantic, mirrored in TS)
- `Point`: {time: str (ISO UTC), forecast_mw: float|null, actual_mw: float|null, publish_time: str|null}
- `ForecastResponse`: {date, cutoff_utc, forecast_as_of_min, forecast_as_of_max, points: Point[], summary: {peak_mw, min_mw, avg_mw, total_mwh}}
- `Metrics`: {mae, rmse, bias, mape, p90_abs_error, worst_over: {time, error_mw}, worst_under: {time, error_mw}, n_points}
- `AccuracyResponse`: {start, end, horizon, metrics: Metrics, by_hour: {hour, mae, bias}[], histogram: {bin_start, bin_end, count}[], by_horizon: {horizon, mae, rmse}[]}
- `TimeseriesResponse`: {start, end, horizon, points: Point[]}
- `MetaResponse`: mirrors meta.json.

## 7. Data quality rules
- Missing actuals or forecasts are left absent (null in API), never zero-filled.
- Rows with null generation dropped at ingest and counted in the ingest log.
- Ingest prints a validation report: row counts, date coverage, duplicates removed, gaps found.
